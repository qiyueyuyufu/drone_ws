GroundStation Serial Protocol
=============================

1. Basic Frame
--------------

Most command packets use the following binary frame:

    HEAD CMD LEN DATA... CHECK TAIL

Field definition:

    HEAD  : 0xAA
    CMD   : 1 byte command id
    LEN   : 1 byte payload length, 0~128
    DATA  : payload bytes, length = LEN
    CHECK : low 8 bits of (CMD + LEN + DATA[0] + ... + DATA[LEN-1])
    TAIL  : 0xFF

Checksum example:

    CHECK = (CMD + LEN + all DATA bytes) & 0xFF

Exception:

    Path drawing frames use the fixed 6-byte format described in section 5.3.
    They do not have the LEN field.


2. Command Enum
---------------

The STM32 code uses these enum names and values:

    GS_CMD_TAKEOFF        = 0x01
    GS_CMD_LAND           = 0x02
    GS_CMD_RETURN_HOME    = 0x03
    GS_CMD_FORBIDDEN_MAP  = 0x10
    GS_CMD_PATH_PLAN      = 0x20    // reserved old multi-packet path command
    GS_CMD_PATH_START     = 0x30
    GS_CMD_PATH_POINT     = 0x31
    GS_CMD_PATH_END       = 0x32
    GS_CMD_ACK            = 0x7F
    GS_CMD_NACK           = 0x7E


3. Debug With Serial Tool
-------------------------

When using SSCOM or another serial tool:

    baudrate: 115200
    data bits: 8
    stop bits: 1
    parity: none
    HEX send: enabled

Example: send TAKEOFF to STM32:

    AA010001FF

Same frame with spaces:

    AA 01 00 01 FF

If STM32 receives this valid frame, it displays RX information in the STATUS
panel and replies ACK:

    AA 7F 01 01 81 FF


4. STM32 -> Onboard Computer
----------------------------

4.1 Takeoff

    CMD  = GS_CMD_TAKEOFF
    LEN  = 0
    DATA = none

Frame:

    AA 01 00 01 FF


4.2 Land

    CMD  = GS_CMD_LAND
    LEN  = 0
    DATA = none

Frame:

    AA 02 00 02 FF


4.3 Return Home

    CMD  = GS_CMD_RETURN_HOME
    LEN  = 0
    DATA = none

Frame:

    AA 03 00 03 FF


4.4 Forbidden Map

    CMD  = GS_CMD_FORBIDDEN_MAP
    LEN  = 99
    DATA = forbidden map cells

The map is 9 rows x 11 columns.

Actual world coordinate:

    x axis: south direction, vertical on screen, 0~4.5 m
    y axis: east direction, horizontal on screen, 0~5.5 m
    cell size: 0.5 m

DATA layout:

    DATA[0]  = row 0, col 0
    DATA[1]  = row 0, col 1
    ...
    DATA[10] = row 0, col 10
    DATA[11] = row 1, col 0
    ...
    DATA[98] = row 8, col 10

Cell value:

    0x00 = free cell
    0x01 = forbidden cell

Frame format:

    AA 10 63 DATA[0] ... DATA[98] CHECK FF


5. Onboard Computer -> STM32
----------------------------

5.1 ACK

Used by the receiver to confirm that a command was received.

The onboard computer can ACK commands sent by STM32.
STM32 can also ACK commands sent by the serial tool or onboard computer during
debugging.

    CMD  = GS_CMD_ACK
    LEN  = 1
    DATA = original command id

Example: ACK for takeoff:

    AA 7F 01 01 81 FF


5.2 NACK

Used by the receiver to report that a command was rejected or invalid.

    CMD  = GS_CMD_NACK
    LEN  = 2
    DATA[0] = original command id
    DATA[1] = error code

Suggested error code:

    0x01 = checksum/frame error
    0x02 = unsupported command
    0x03 = invalid payload length
    0x04 = command rejected by current flight state


5.3 Path Drawing, Fixed 6-byte Frames
-------------------------------------

Current STM32 route drawing uses fixed 6-byte path frames.

These frames do NOT use the normal LEN field. The format is:

    HEAD TYPE A B CHECK TAIL

Field definition:

    HEAD  : 0xAA
    TYPE  : path frame type
    A     : row or 0
    B     : column or 0
    CHECK : low 8 bits of (TYPE + A + B)
    TAIL  : 0xFF

Path frame enum:

    GS_CMD_PATH_START = 0x30
    GS_CMD_PATH_POINT = 0x31
    GS_CMD_PATH_END   = 0x32

Path start:

    AA 30 00 00 30 FF

Meaning:

    Clear the old displayed route, keep forbidden cells, and begin receiving
    path points.

Path point:

    AA 31 ROW COL CHECK FF

Meaning:

    ROW: map row, 1~9
    COL: map column, 1~11

The row and column are grid coordinates shown on the STM32 screen.
The route line is drawn through the center of each cell.

Example: row 1, column 1

    CHECK = 0x31 + 0x01 + 0x01 = 0x33
    AA 31 01 01 33 FF

Example: row 3, column 5

    CHECK = 0x31 + 0x03 + 0x05 = 0x39
    AA 31 03 05 39 FF

Path end:

    AA 32 00 00 32 FF

Meaning:

    Stop receiving this route. The displayed route remains on the map.

ACK behavior:

    STM32 replies ACK after receiving each valid start, point, or end frame.

Example ACK for one valid path point:

    AA 7F 01 31 B1 FF

Invalid behavior:

    STM32 displays "Invalid" when:

    checksum is wrong
    tail is not 0xFF
    frame times out after 0xAA
    row is not in 1~9
    column is not in 1~11
    a path point is received before path start

Reserved old command:

    GS_CMD_PATH_PLAN = 0x20

This old multi-packet command is reserved and not used by the current route
drawing debug flow.

6. STM32 Receive Flow
---------------------

USART interrupt receives one byte each time.

Each received byte is passed to:

    GS_Protocol_RxByte(byte)

The parser state machine reads:

    WAIT_HEAD -> CMD -> LEN -> DATA -> CHECK -> TAIL

For fixed 6-byte path frames, the parser reads:

    WAIT_HEAD -> TYPE -> A -> B -> CHECK -> TAIL

Receive timeout:

    If STM32 receives HEAD 0xAA and enters a frame-receiving state, but no
    complete valid frame is received within 50 ms, STM32 resets the parser and
    displays:

        Invalid

    Example invalid half frame:

        AA FF

    This does not form a complete valid frame, so after 50 ms STM32 displays
    "Invalid".

When a complete valid frame is received, the application can call:

    GS_Protocol_GetFrame(&cmd, data, &len)

Then handle different commands:

    GS_CMD_TAKEOFF
    GS_CMD_LAND
    GS_CMD_RETURN_HOME
    GS_CMD_ACK
    GS_CMD_NACK
    GS_CMD_PATH_START
    GS_CMD_PATH_POINT
    GS_CMD_PATH_END

Current debug behavior:

    RX GS_CMD_TAKEOFF      -> display "RX TAKEOFF", reply ACK
    RX GS_CMD_LAND         -> display "RX LAND", reply ACK
    RX GS_CMD_RETURN_HOME  -> display "RX RETURN", reply ACK
    RX GS_CMD_PATH_START   -> clear old route, display "PATH START", reply ACK
    RX GS_CMD_PATH_POINT   -> draw line to cell center, display "PATH POINT", reply ACK
    RX GS_CMD_PATH_END     -> finish route, display "PATH END", reply ACK
    RX invalid path point  -> display "Invalid"
    RX unknown command     -> display "RX UNKNOWN"

7. STATUS Panel Debug Display
-----------------------------

The STM32 screen STATUS panel displays the latest transmitted and received
frames.

For short frames:

    TX: AA 01 00 01 FF
    RX: AA 01 00 01 FF

For long frames:

    TX: AA 10 63 ... CHECK FF
    PAYLOAD: 63h


8. Notes
--------

Current protocol does not escape 0xAA or 0xFF inside DATA.

This is acceptable for early testing because LEN controls the payload length.
The parser only treats 0xFF as frame tail after it has already received CMD,
LEN, DATA and CHECK.

If the protocol needs stronger reliability later, add:

    sequence id
    timeout/retry
    CRC16 instead of 8-bit checksum
    optional data escaping
